# keitaro-campaign-manager

Обёртка над рекламным трекером [Keitaro](https://keitaro.io): создание кампаний с двумя потоками и редактор офферов существующей кампании.

Сейчас готов **шаг 1: скелет**. Это FastAPI-приложение, подключение к MySQL, миграции Alembic, модель кампании и проверка готовности `GET /health`. Клиент Keitaro и создание кампаний появятся на следующих шагах (см. план ниже).

Стек: Python 3.11+, FastAPI, SQLAlchemy 2.0, Alembic, MySQL 8.4.

## Быстрый старт (Docker)

```bash
cp .env.example .env      # заполни пароли и префикс имён кампаний
docker compose up --build
```

Миграции применяются автоматически при старте контейнера `app`. Проверка:

```bash
curl http://localhost:8000/health   # {"status":"ok"}
```

Документация API (Swagger) открывается на http://localhost:8000/docs.

## Запуск на хосте (для отладки)

В Docker поднимается только база, приложение работает из виртуального окружения, и его удобно отлаживать в IDE.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
docker compose up -d db        # только MySQL
alembic upgrade head
uvicorn app.main:app --reload
```

Если порт 3306 на хосте занят, поменяй `DB_PORT` в `.env`.

## Миграции

```bash
alembic upgrade head                                  # применить все
alembic downgrade -1                                  # откатить последнюю
alembic revision --autogenerate -m "описание"         # создать новую по изменениям моделей
alembic check                                         # модели и миграции совпадают?
alembic upgrade head --sql                            # показать SQL, не подключаясь к базе
```

Автогенерацию нужно просматривать глазами: Alembic не всегда верно угадывает переименования.

## Проверки

```bash
python -m pytest
ruff check .
ruff format --check .
mypy
```

Тесты не требуют MySQL и сети: репозиторий проверяется на SQLite в памяти.

## Структура

```
app/
├── constants.py        # все числа, строки и тексты ошибок
├── config.py           # настройки из окружения (.env в разработке)
├── domain/             # правила кампании: чистый Python, без I/O
├── application/        # порты (интерфейсы), позже сценарии
├── adapters/
│   ├── db/             # исходящий адаптер: SQLAlchemy и MySQL
│   └── api/            # входящий адаптер: FastAPI
└── main.py             # composition root: связывает всё воедино
alembic/                # миграции
tests/
```

Зависимости направлены внутрь: адаптеры знают о ядре, ядро об адаптерах не знает.

## Принятые решения

- **MySQL и PyMySQL.** Драйвер на чистом Python, ему не нужны системные библиотеки. Пакет `cryptography` требуется для аутентификации MySQL 8.
- **Синхронный стек.** Обычные `def`-эндпоинты и синхронная сессия SQLAlchemy: у приложения немного вызовов, а `async` добавил бы сложности без выигрыша.
- **Источник правды о содержимом кампании это Keitaro.** Локальная таблица `campaigns` это реестр: что мы создали, с какими параметрами и на каком этапе создание (`pending`, `active`, `failed`). Благодаря ему прерванное создание не теряется, а редактор показывает только наши кампании.
- **Каждое изменение реестра фиксируется сразу.** Запись `pending` должна пережить падение в середине создания.
- **Префикс имён.** К имени каждой кампании добавляется префикс из `CAMPAIGN_NAME_PREFIX`, если его там ещё нет, чтобы не затронуть чужие кампании на общем трекере.
- **Секреты только из окружения.** `.env` не попадает в Git, образец лежит в `.env.example`.

## План

1. Клиент Keitaro (порт и адаптер на httpx), справочники, поиск офферов.
2. Сценарий создания кампании: запись `pending`, кампания, два потока, `active`; откат при сбое.
3. API и HTML-форма создания.
4. Редактор офферов с пересчётом долей.
